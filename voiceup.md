# Assessment Task: VoiceUp — Campus Feedback API

## 1. Project Description

Develop a REST API for a campus feedback system using Django REST Framework. Users can register, log in, submit feedback, and manage their own feedback. The system should support feedback categorization and sentiment analysis.

## 2. Feedback Table Fields

| Field | Data Type | Description |
|---|---|---|
| `id` | Integer, Primary Key | Unique feedback ID; auto-generated |
| `student` | Foreign Key to User | User who submitted the feedback |
| `department` | Choice / String | Department selected by the student |
| `feedback_text` | Text | Feedback content |
| `sentiment` | Choice / String | Positive, negative, neutral, or unknown |
| `category` | Choice / String | Faculty, academics, infrastructure, administration, facilities, or other |
| `created_at` | DateTime | Feedback creation timestamp; auto-generated |

### Department Choices

## 3. API Endpoints to Implement

### A. Authentication APIs

| Method | Endpoint | Description |
|---|---|---|
| POST | `/api/auth/signup/` | Register a new user |
| POST | `/api/auth/signin/` | Authenticate a user and return the configured authentication response |

### B. Feedback APIs

| Method | Endpoint | Description |
|---|---|---|
| GET | `/api/feedback/` | List feedback accessible to the logged-in user |
| POST | `/api/feedback/` | Create new feedback |
| GET | `/api/feedback/<id>/` | Retrieve feedback details |
| PATCH | `/api/feedback/<id>/` | Partially update feedback |
| DELETE | `/api/feedback/<id>/` | Delete feedback |

### C. Feedback Analytics API

| Method | Endpoint | Description |
|---|---|---|
| GET | `/api/feedback/summary/` | Return feedback counts grouped by sentiment and category |

## 4. Functional Requirements

1. Users must be able to register and authenticate.
2. Only authenticated users can access protected feedback endpoints.
3. The logged-in user must be assigned as the owner when feedback is created.
4. Users can view, update, and delete only their own feedback.
5. Users must not be allowed to change the feedback owner by submitting a different user ID.
6. Validate the department and feedback text before saving.
7. Sentiment and category should be generated by an AI model or assigned by a clearly defined backend rule. Users must not be able to manipulate AI-generated fields through ordinary feedback submissions.
8. Return suitable HTTP status codes and structured JSON responses.
9. The summary endpoint should provide counts grouped by sentiment and category for the feedback the requesting user is authorized to access.
